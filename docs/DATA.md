# Data availability and schemas

This snapshot includes compact summaries sufficient to regenerate all 14 paper figures and 14 numerical paper tables. SHA-256 hashes and source-relative paths appear in `audit/source-manifest.json`. `audit/SHA256SUMS.json` covers the release files themselves. Copied numerical summaries retain their original bytes. The additional `ana/low-load-counts.tsv` was computed from server replay records on 2026-10-28; it does not replace any historical summary.

## Included

`sim/results/exp6-20261016/coverage.tsv` stores stage, sampling kind, configuration, rule, risk, failure counts, miss rates, intervals, empty-set rates, and width summaries. `protocol.tsv` stores per-configuration and per-arm protocol outcomes, conditional and joint misses, final failure rates, mean table sizes, and bytes. `c2*.tsv` records confirmation judgments and simultaneous upper confidence bounds. `ana/` contains distribution and paired-comparison summaries. `T/` contains individual timing summaries and protocol timing replicates.

The sampler writes `manifest.json` describing configuration metadata, seeds, code version, field names, and the binary record layout. Records are little-endian four-byte fields; exact count sums are enabled by `-sumc`. Use the manifest and `sim/peelsim/peelio.py` to interpret each run rather than assuming a fixed field ordering. Replay outputs contain per-configuration groups, counts, miss counts, empty counts, and width histograms.

Protocol `-trialout` records `spec,trial,arm,U,M2,ok2` for first-round failures. `U=-1` encodes an empty acceptance set. Aggregate CSVs also contain wall-clock timing fields, which vary across repeated runs. `ana/trialcheck.json` records the per-trial check of these files against the aggregates (see `docs/AUDIT.md`).

## Required for full historical reproduction

Archive the original sampler binary records, per-block manifests, replay outputs, protocol trial CSVs, completed-task records, compiler and hardware metadata, and decoder audit checkpoints. Supply a stable download URL, archive SHA-256, size, and license for each batch. These records are not bundled in the repository. They are published as an asset of the GitHub release v0.1.2, https://github.com/whitewum/random-sign-artifact/releases/tag/v0.1.2, as `random-sign-raw-20261028.tar.xz`: 1,260,741,276 bytes, 185,935 entries, SHA-256 `f7af591fc9f9b905741583f96ac7762646d2f41c405aa0fbeaf53bda345024c7`, MIT License; the release also carries `random-sign-raw-20261028.SHA256SUMS`. The source of each release is archived at Zenodo, https://doi.org/10.5281/zenodo.23754604 (all versions). Paths inside the archive are relative to the historical archive root used in `docs/SERVER-CHECK.md`. The 2026-10-28 server verification located and inventoried the records, ran historical checks, and generated a 6,107,788,635-byte archival recommendation (uncompressed inputs). `docs/SERVER-CHECK.md` records the exact scope and results. Inventory hashes certify path/size listings; they are not hashes of raw payload contents. Decoder checkpoint files, encoding CSVs and historical executables also have payload SHA-256 records.

Source manifests identify this working-tree snapshot. They do not establish that these exact source bytes produced every historical summary: some decoder files were modified or untracked at snapshot time. Preserve original binary hashes and source archives alongside the historical trial data to complete that association.

## Paper tables and analytic figures

`make tables` generates all 14 numerical tables in `outputs/tables/` from the existing result summaries, timing replicate CSVs and exact enumeration. No trial archive is downloaded. Each TSV follows the paper row and column order; paired numbers and ranges use ` ; `, percentages are in percentage points, and values retain source precision. `tab-extra.tsv` has two blocks with different column counts, matching the two adjacent paper tabular environments. `scripts/tables.py` documents the selection and aggregation rules. The right block of `tab:extra` pools the configuration medians at each c over all four table sizes and three k values.

The exact encoding table imports `theory/scripts/check_random_sign_encoding.py`, enumerates every mapping multiset and sign vector with exact rational arithmetic, and verifies the archived `theory/diagnostics/random-sign-encoding-exact.json`. Its archived case parameters select the six configurations; archived outcome values are only assertions, never output inputs. `sim/results/analytic/aux-parameters.json` and `structure-mapping.json` were extracted from the original figure programs, and supply the analytic null law and illustrative diagram. Figure generation also writes their computed numerical points and cell counts to `outputs/figures/`.

`audit/paper-inventory.json` records every CN figure/table label, source location and source hash without copying Chinese text. `audit/table-reference.json` is a numeric-only comparison oracle automatically extracted from CN; it is not used by `make tables`. Refresh or compare against a read-only manuscript tree with `scripts/check_tables.py --cn PATH` (add `--snapshot` only to intentionally refresh the oracle). Neither operation writes to the source tree. The default check needs only artifact files. Every printed numeric token, including configuration columns and exact fractions, is checked. Decimal values must lie within half a unit of the paper's last printed digit; either conventional rule is accepted at exact rounding ties, with 1e-12 tolerance for floating arithmetic. This is a comparison at displayed precision, not byte equality or an assertion about unpublished digits.

The historical low-load comparison TSVs preserve three decimal places of miss/u and interval endpoints. `sim/results/exp6-20261016/ana/low-load-counts.tsv` now preserves all 48 `(id, kind, u)` integer count rows: `n_fail`, `miss`, `blocks`, and the contributing `stages`. Final direct samples use v2 for k=3 and v3a or pooled v3b/v3c for k=4,5; planted samples use v2 or v2s. `scripts/tables.py` computes rates and normal difference intervals from these counts. They resolve all three rounding boundaries. One manuscript cell needs correction: the first planted miss/u is 3072/65000/0.05 = 0.945230769..., which displays as 0.95, not 0.94. The manuscript cell and the comparison oracle have been corrected accordingly; see `docs/SERVER-CHECK.md`. No count was inferred from manuscript values. Similarly, timing TSVs reproduce recorded medians, not new hardware measurements. `tab:sizing-options` and the unlabeled notation table are descriptive, so no numerical dataset is required.
